# 미유 상담 흐름·해설 콘텐츠 설계

## 목적

미유를 컨설턴트가 고객과 함께 보는 태블릿 상담 도구로 만든다. 고객은 자신의 언어와 한국어를 함께 보며 무드와 스타일 방향을 이해하고, 컨설턴트는 한국어 진단 화면에서 선택과 최종 타입 결정을 진행한다.

## 적용 순서

`고객 정보 → 소개 3장 → 진단 시작 브릿지 → 컨설턴트용 진단 → 고객용 해설`

### 1. 고객 정보

처음에 고객명, 컨설턴트명, 해설 언어(`ja`, `zh-CN`, `zh-TW`), 성별, 진단일을 받는다. 이 정보는 현재처럼 `sessionStorage`에만 유지한다.

성별을 먼저 받으므로 이후 B 그룹은 여성에게 `Feminine · 페미닌`, 남성에게 `Boyish · 보이시`로 표시할 수 있다.

### 2. 미유 무드 진단 소개

소개는 PPT 1~3페이지를 태블릿 세로 화면에 맞는 3개 화면으로 나눈다. 각 문장은 한국어와 선택 언어를 같은 의미 단위로 함께 표시한다.

1. **미유 무드 진단이란?**
   - 사람마다 얼굴 형태, 이목구비 구조, 분위기와 전체 인상에 따라 어울리는 스타일이 다르다.
   - 미유는 예쁨이나 잘생김을 판단하지 않고, 나만의 분위기를 가장 매력적으로 표현할 스타일을 찾는다.
   - 얼굴 구조와 인상을 바탕으로 무드를 4개 그룹으로 분류한다.
2. **4개의 무드 그룹**
   - Blossom: 화사하고 사랑스러운
   - Feminine 또는 Boyish: 부드럽고 우아한 / 부드러운 소년미
   - Mood: 분위기와 개성이 돋보이는
   - Modern: 선명하고 세련된 도시적인
3. **무드 진단이 필요한 이유**
   - 억지스럽지 않게 장점을 살리는 방향을 찾는다.
   - 스타일 선택의 실패를 줄이고 일관된 이미지를 만든다.
   - 결과를 메이크업, 헤어, 패션, 액세서리 제안으로 연결한다.

소개 마지막에는 `지금부터 진단을 시작하겠습니다` 화면과 한국어 `진단 시작` 버튼을 둔다. 고객용 문장은 이중언어로, 조작 버튼과 진단 단계 표기는 한국어로 유지한다.

### 3. 진단

기존 10문항, 최대 2개 선택, ABCD 합산, 1·2위 표시, 컨설턴트의 최종 12타입 선택은 유지한다. 진단 문항·진행표·점수표·타입 선택은 컨설턴트 전용이며 한국어만 표시한다.

### 4. 고객용 해설

선택 타입의 해설은 아래 순서를 고정한다. 모든 고객 노출 텍스트는 한국어와 선택 언어를 나란히 표시한다.

1. **이목구비 특징**: 기존 대표 특징 요약과 상세 특징 10행
2. **이 무드가 주는 분위기**: 타입명, 무드 설명, 정의, 키워드
3. **메이크업**: 12개 세부 타입별 PPT 기준 추천과 피해야 할 방향
4. **헤어**: A/B/C/D 대분류의 공통 방향. 여성·남성은 각각 PPT의 그룹 헤어 기준을 쓴다.
5. **액세서리·패션**: 여성은 PPT의 타입별 스타일링 기준을 반영한다. 남성은 PPT의 남성 키워드·헤어·인상 방향을 바탕으로 한 간단한 초안 추천을 제공한다.

기존 정의·키워드·스타일 섹션의 중복은 제거하거나 위 순서의 단일 섹션 안으로 합친다. 고객 화면에는 `초안`, `검토 메모` 같은 내부 표기를 노출하지 않는다.

## 콘텐츠 데이터 경계

`src/explanation-data.js`에 다음 데이터 단위를 추가한다.

- `INTRO_PAGES`: 소개 3장의 문장과 4개 그룹 카드. 모든 문구는 `ko`, `ja`, `zh-CN`, `zh-TW`를 가진다.
- `BRIDGE_COPY`: 진단 시작 전 안내 문구. 모든 문구는 네 언어를 가진다.
- 각 타입의 `recommendations.makeup`: 여성·남성별 12개 타입 메이크업 추천·피해야 할 방향.
- `GROUP_HAIR`: A/B/C/D × 여성·남성의 공통 헤어 추천·피해야 할 방향.
- 각 타입의 `recommendations.accessoryFashion`: 여성 PPT 기준과 남성 초안의 액세서리·패션 추천.

`getExplanation(typeCode, gender, language)`은 위 데이터를 기존 해설 데이터와 함께 반환한다. 고객용 데이터는 언어 하나라도 비거나 타입·성별 항목이 빠지면 `assertCompleteContent()`가 빌드를 실패시킨다.

## 화면·라우팅 경계

- 프로필 저장 뒤 `#/diagnosis/intro/1`로 이동한다.
- 소개 다음은 `#/diagnosis/intro/2`, `#/diagnosis/intro/3`, `#/diagnosis/bridge`, `#/diagnosis/question/1` 순서다.
- 뒤로가기는 소개·브릿지·문항 전체에서 이전 단계로 이동한다.
- 고객용 해설 화면은 이 설계의 순서로만 섹션을 렌더한다.
- 기존 직접 타입 링크와 컨설턴트 점수 선택은 유지한다.

## 검증 기준

- 진단 프로필이 없으면 소개·브릿지·문항 화면에 진입하지 못한다.
- 여성/일본어와 남성/번체 경로에서 소개 3장과 해설 5개 섹션이 한국어+선택 언어로 보인다.
- 진단 문항과 점수·타입 선택에는 선택 언어 문장이 섞이지 않는다.
- 12타입 × 2성별의 메이크업·액세서리·패션, 4그룹 × 2성별의 헤어 데이터가 모두 완전해야 한다.
- PPT 기준의 타입명 연결은 `A-1 Fantasy`, `A-2 Fruity`, `A-3 Soda`, `B-1 Romantic`, `B-2 Soft`, `B-3 Elegance`, `C-1 Vintage`, `C-2 Refined`, `C-3 Deep Chic`, `D-1 Clear`, `D-2 Sharp`, `D-3 Charisma`로 고정한다.

## 관련 배포 보완

이 설계는 `2026-08-09-miyu-deployable-standalone-design.md`의 단일 HTML·95 MiB 제한·동적 영문 연예인명·남성 레거시 경계와 함께 구현한다. 이 상담 흐름은 이미지 최적화나 점수·타입 매핑을 바꾸지 않는다.

## 비범위

- 원본 PPT와 v16은 수정하지 않는다.
- 남성 대분류·무드북의 새 콘텐츠를 작성하지 않는다. 준비되지 않은 여성 전용 레거시 경로는 남성 세션에서 차단한다.
- 실제 iPad 검증과 GitHub Pages 배포는 코드·콘텐츠 검수 완료 뒤 별도 게이트로 남는다.
