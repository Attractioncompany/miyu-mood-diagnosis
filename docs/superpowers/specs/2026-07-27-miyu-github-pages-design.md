# 미유 무드 진단 GitHub Pages 공개 배포 설계

작성일: 2026-07-27  
상태: 사용자 승인 완료

## 1. 해결할 고객 불편

현재 완성본은 특정 맥의 로컬 파일로만 열 수 있어 태블릿과 다른 기기에서 바로 접근하기 어렵다. 컨설턴트가 별도 설치 없이 웹 링크 하나로 진단 프로그램을 열 수 있도록 공개 배포한다.

## 2. 확정 조건

- GitHub 계정: `Attractioncompany`
- 공개 저장소: `miyu-mood-diagnosis`
- 공개 주소: `https://attractioncompany.github.io/miyu-mood-diagnosis/`
- 기본 브랜치: `main`
- 배포 대상: `dist` 폴더만
- 완성본: `dist/미유_무드진단_12type_v17.html`

공개 저장소를 사용하므로 저장소의 진단 콘텐츠와 이미지 파일은 누구나 열람하고 내려받을 수 있다. 사용자는 이 조건과 약 61MB 단일 HTML의 첫 로딩 부담을 확인하고 공개 배포를 승인했다.

## 3. 검토한 방식

### A. GitHub Pages와 공식 Actions 사용 — 채택

`main` 브랜치가 갱신되면 GitHub의 공식 배포 작업이 `dist` 폴더만 Pages에 올린다.

- 장점: 무료 공개 링크, 이후 갱신 자동화, 소스·테스트 파일은 웹사이트 경로에서 제외
- 단점: 저장소 자체는 공개이며 첫 로딩 파일이 크다

### B. 브랜치 전체를 Pages로 공개

- 장점: 설정이 더 단순하다
- 단점: 웹사이트에 필요 없는 개발 파일까지 배포 범위에 섞이기 쉽다

### C. 별도 상용 호스팅

- 장점: 비공개 배포, 접근 제어, 용량 최적화 선택지가 넓다
- 단점: 계정·비용·운영 설정이 추가된다

현재 목표는 빠르게 링크로 공유하는 것이므로 A를 채택한다.

## 4. 배포 구조

1. `dist/index.html`은 짧은 루트 주소로 들어온 사용자를 실제 v17 파일로 즉시 연결한다.
2. `.github/workflows/pages.yml`은 `main` 푸시와 수동 실행을 지원한다.
3. 워크플로는 읽기 권한과 Pages 배포에 필요한 최소 권한만 사용한다.
4. 배포 아티팩트는 `dist`로 제한한다.
5. 동시에 여러 배포가 실행되면 최신 작업을 우선한다.

## 5. 오류 처리

- Pages가 아직 활성화되지 않은 경우 저장소 생성 후 Pages의 배포 방식을 `GitHub Actions`로 설정한다.
- 첫 자동 배포가 활성화 순서 때문에 실패하면 동일 워크플로를 수동으로 다시 실행한다.
- 배포 실패 시 GitHub Actions 로그를 확인하고 성공 전에는 공개 완료라고 보고하지 않는다.
- 루트 리다이렉트가 작동하지 않아도 화면의 직접 링크로 v17 파일을 열 수 있게 한다.

## 6. 검증 기준

- 공개 저장소가 `Attractioncompany/miyu-mood-diagnosis`에 존재한다.
- 로컬 `main`과 GitHub의 `main`이 같은 커밋을 가리킨다.
- Pages 배포 작업이 성공 상태다.
- 루트 공개 주소가 정상 응답하며 v17 진단 화면으로 연결된다.
- 배포 설정이 `dist` 밖의 파일을 사이트 아티팩트에 포함하지 않는다.
- 기존 진단 자동 검증이 계속 통과한다.

## 7. 이후 개선 후보

약 61MB 단일 HTML은 공개 링크의 첫 실행 속도에 불리하다. 실제 현장 사용에서 로딩 지연이 확인되면 이미지 파일 분리·압축과 브라우저 캐시 적용을 별도 작업으로 검토한다. 이번 배포에서는 검증된 단일 파일 구조를 바꾸지 않는다.
