# MIYU 해설 쇼케이스·패션 가이드 설계

## 목표

컨설턴트와 고객이 태블릿에서 해설을 볼 때, 한 장의 콜라주를 해석해야 하는 불편을 없앤다. 진단을 생략해도 성별·언어·타입을 골라 해설을 열 수 있고, 각 유형의 스타일 참고와 일상 코디 방향을 사진·짧은 설명으로 함께 확인한다.

## 화면 흐름

1. 시작 화면에 `해설 바로보기` 보조 버튼을 둔다. 진단일 없이 해설 언어와 성별만 선택한다.
2. `#/explanation/{gender}/{language}`는 12개 타입 선택 화면을 연다. 이 화면의 여성/남성 전환은 같은 언어를 유지한다.
3. `#/explanation/{gender}/{language}/{type}/{page}`는 세션 정보 없이도 고객용 해설을 직접 렌더한다. 진단 결과 화면의 기존 해설 경로는 계속 유지한다.
4. 해설 하단의 `다른 타입 해설 보기`는 현재 성별·언어의 타입 선택 화면으로 이동한다. 타입 선택 화면에서 성별을 바꿀 수 있어 여성·남성 해설을 교차 탐색할 수 있다.

## 이미지와 페이지 구조

- 메이크업/그루밍, 헤어의 참고 이미지는 한 장의 복합 콜라주 대신 최대 3장의 개별 카드로 제공한다.
- 카드 목록은 한 줄 가로 스크롤이며 태블릿 세로 화면에서 약 3장이 보인다. 각 카드는 이미지 아래에 한국어와 선택 언어로 "무엇을 볼 사진인지"를 짧게 표기한다.
- 기존 8개 해설 페이지의 마지막 패션 페이지는 2개로 분리한다.
  1. `스타일 레퍼런스`: PPT 속 아이돌·연예인 스타일 사진에서 쓸 수 있는 이미지를 개별 카드로 제시한다. 사진은 인물 식별을 강요하지 않고, 실루엣/색/무드 중심의 설명을 붙인다.
  2. `데일리 코디 제안`: 타입별 생성 코디 3세트와 함께 소재·패턴·디자인, 액세서리(크기·형태·색), 조합 시 유의사항을 제공한다.
- PPT에서 꺼낸 이미지는 우선 사용하고, 개별 사진으로 나누기 어려운 경우에만 PPT의 타입 특징을 입력값으로 한 생성 이미지로 보완한다.
- 모든 고객 노출 캡션과 데일리 코디 설명은 한국어·일본어·중국어 간체·중국어 번체를 갖는다. 초안 문구는 이후 검수하기 쉬운 타입별 데이터로 둔다.

## 데이터와 자산

- `sections.makeup`, `sections.hair`, `sections.accessoryFashion`은 복수 `examples`를 지원하며, 각 항목은 `{ image, caption }`으로 표현한다.
- 데일리 코디는 타입·성별별 `dailyOutfits` 3세트로 표현한다. 각 세트는 이미지와 소재/패턴/디자인/액세서리/유의사항의 다국어 텍스트를 가진다.
- 새 JPEG는 360px 내외 카드용으로 최적화해 단일 HTML이 95MiB 제한을 넘지 않게 한다. 기존 단일 HTML은 약 69MiB이므로 새 참조 이미지는 압축 저장한다.

## UI 원칙

- 페이지형 해설은 한 번에 하나의 주제만 보여준다.
- 가로 스크롤은 카드의 가장자리가 다음 항목을 살짝 보이게 해 스크롤 가능함을 알린다. 스크롤바는 숨기지 않는다.
- 고객이 읽는 한국어는 굵고 크게, 번역문은 바로 아래에 보조 크기로 둔다.
- 카드·제목·버튼의 간격은 태블릿 세로 834×1194에서 한 섹션이 답답하거나 과도하게 비지 않게 맞춘다.

## 검증

- 세션 없이 직접 해설 경로를 열고, 진단 경로와 별개로 해설이 렌더되는지 확인한다.
- 타입 선택에서 여성↔남성 전환 및 언어 유지, 해설의 `다른 타입 해설 보기` 동작을 자동 검증한다.
- 834×1194 태블릿에서 예시 카드가 가로 한 줄이며 2~3장이 보이고, 카드별 한국어·번역 캡션이 렌더되는지 확인한다.
- 해설 페이지 수가 9개가 되고 패션 레퍼런스·데일리 코디가 순서대로 분리되는지 확인한다.
- 빌드 최신성, 모든 자산 내장, 95MiB 제한, 전체 Node/Python 검사를 통과해야 배포한다.
