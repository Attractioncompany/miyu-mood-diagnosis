# MIYU PPT 스타일링 원문 반영 및 해설 병합 설계

## 목적

고객이 보는 해설에서 같은 무드 설명이 반복되는 문제를 없애고, 제공받은 PPT의 추천·피하면 좋은 헤어 및 메이크업 원문을 타입에 맞게 보여 준다.

## 근거와 범위

- 해설 1·2·5페이지는 한 페이지로 병합한다. 기존 1·5페이지에 같은 무드 요약이 반복되므로, 하나의 `무드 정체성` 페이지에서 무드 설명·평균 얼굴·대표 이목구비·정의·키워드를 함께 보여 준다.
- 이목구비 상세 2페이지, 추천/피하면 좋은 메이크업 2페이지, 추천/피하면 좋은 헤어 2페이지, 액세서리·패션 1페이지는 유지한다. 전체 해설은 10페이지에서 8페이지가 된다.
- 헤어는 PPT의 대분류 공통 가이드로 처리한다. PPT 118페이지에는 헤어를 소분류 1·2·3으로 나누는 것은 무의미하며 전체 느낌이 중요하다고 명시돼 있다.
  - A 블로썸: 여성 6/10페이지, 남성 12/14페이지
  - B 페미닌: 여성 35/36페이지, 남성 41/43페이지
  - C 무드: 여성 64/65페이지, 남성 69/71페이지
  - D 모던: 여성 92/93페이지, 남성 97/99페이지
- 메이크업은 12개 세부 타입별 PPT 가이드를 처리한다. 여성은 추천과 피하면 좋은 방향을 각 타입의 원문 핵심으로, 남성은 해당 타입 PPT의 그루밍 지침을 우선하고 없는 경우 대분류 공통 그루밍으로 보완한다.
- D그룹은 앱의 화면 코드 순서와 PPT 코드 순서가 다르다. 문구 연결은 코드 번호가 아닌 타입명으로 처리한다.
  - 앱: D-1 카리스마, D-2 클리어, D-3 샤프
  - PPT: D-1 클리어, D-2 샤프, D-3 카리스마

## 화면 구조

1. 무드 정체성: 무드 설명, 평균 얼굴, 대표 이목구비, 타입 정의, 키워드
2. 이목구비 상세 1
3. 이목구비 상세 2
4. 추천 메이크업 또는 남성 그루밍
5. 피하면 좋은 메이크업 또는 남성 그루밍
6. 추천 헤어
7. 피하면 좋은 헤어
8. 액세서리·패션

태블릿 세로에서는 정체성 페이지를 평균 얼굴 → 핵심 특징 → 무드 설명 순으로 한 열 배치한다. 가로에서는 평균 얼굴과 텍스트를 두 열로 배치한다. 한 장 안에 모든 내용을 억지로 축소하지 않고, 기존의 상세 이목구비 두 장은 유지한다.

## 데이터와 연결 방식

- 대분류 헤어 데이터는 `GROUP_HAIR`와 `GROUP_HAIR_AVOID`에 PPT 원문 핵심을 보강한다.
- 세부 메이크업 데이터는 타입 코드가 아닌 `type.name`을 기준으로 조회하는 새 원문 가이드 맵을 둔다. D그룹의 콘텐츠가 잘못 붙는 회귀를 방지한다.
- 여성 D-2 클리어는 PPT에 별도의 추천/피하면 좋은 항목 텍스트가 없으므로, 해당 타입의 피부·색감·느낌·포인트 설명과 BEST/WORST 이미지 방향을 바탕으로 명확히 작성한다. 없는 PPT 문장을 원문처럼 표기하지 않는다.
- 추천/피하면 좋은 예시 이미지는 기존 PPT 기반 이미지를 유지한다. 같은 이미지를 추천과 회피에 반복 사용할 경우, 캡션은 각각의 방향에 맞춰 구분한다.

## 호환성과 안전장치

- 새 해설 주소 형식 `#/diagnosis/explanation/{type}/{page}`은 유지한다. 새 페이지 배열 길이에 맞게 범위를 1~8로 제한한다.
- 기존 북마크의 페이지 번호 의미는 일부 달라진다. 과거 1·2·5페이지는 모두 새 1페이지로 자연스럽게 연결하도록 페이지 인덱스를 정규화한다.
- 기존 레거시 `#/cat/{id}` 해설 패널은 새 해설 첫 페이지로 연결해, 페이지 이동 버튼이 앱 바깥에서 동작하지 않던 문제를 피한다.
- 모든 고객 노출 내용은 한국어와 선택 언어를 함께 유지한다.

## 검증

- 단위 테스트에서 8페이지 순서, 병합 페이지 중복 제거, 대분류 헤어 연결, 12타입 메이크업 연결, D그룹 이름 기반 연결을 확인한다.
- UI 테스트에서 병합 페이지의 평균 얼굴·핵심 특징·무드 문구, 스타일링의 추천/피하면 좋은 문구·사진, 레거시 직접 해설 연결을 확인한다.
- 태블릿 세로·가로 브라우저 검사에서 병합 페이지의 가로 넘침과 이미지 잘림을 확인한다.
- 빌드를 다시 만들어 정식 Full V1 단일 HTML과 기존 v17 연결 페이지를 최신 상태로 맞춘다.
