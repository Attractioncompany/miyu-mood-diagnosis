# 미유 무드 진단 앞단 추가 설계

작성일: 2026-07-27  
상태: 화면·상호작용 방향 사용자 승인 완료

## 1. 해결할 고객 불편

컨설턴트가 종이 진단지에서 답을 체크하고 ABCD 점수를 따로 계산한 뒤, 다시 12타입 해설을 수동으로 찾아야 한다. 이 과정에서 계산 누락, 타입 순서 혼동, 잘못된 해설 이동이 발생할 수 있다.

이번 개발은 기존 해설용 HTML 앞에 디지털 진단 단계를 추가해 입력, 계산, 최종 타입 선택, 해설 이동을 한 흐름으로 연결한다.

## 2. 목표

1. PDF 진단지의 10문항을 한 문항씩 순서대로 진행한다.
2. 문항별로 최소 1개, 최대 2개 답을 선택한다.
3. 선택한 A/B/C/D 항목마다 각각 1점을 더한다.
4. 10문항 완료 후 A/B/C/D 합산표를 표시한다.
5. 1위와 2위 그룹을 명확히 표시하되 12타입 전체를 선택 가능하게 유지한다.
6. 컨설턴트가 선택한 최종 세부타입의 기존 해설로 바로 이동한다.
7. 세로 태블릿 사용을 1순위로 최적화하고 가로 화면도 정상 지원한다.
8. 기존 v16 원본은 보존하고 새 결과물은 v17로 만든다.

## 3. 범위 밖

- 진단 기준이나 배점의 타당성 자체를 이번 개발에서 재설계하지 않는다.
- 서버, 회원가입, 클라우드 저장, 고객 데이터 전송은 추가하지 않는다.
- 기존 해설 콘텐츠의 문장·인물 분류를 전면 수정하지 않는다.
- 기존 62MB 단일 HTML을 여러 파일 구조로 전면 개편하지 않는다.
- PDF 예시 이미지의 저해상도 원본을 임의 생성 이미지로 교체하지 않는다.

## 4. 기준 자료

- 기존 해설: `source/미유_무드분류_12type_v16.html`
- 진단 문항과 순서: `reference/무드 체크 리스트. ver2.pdf`
- 브랜드 로고: `assets/로고.png`
- 최종 산출물: `dist/미유_무드진단_12type_v17.html`

최종 산출물은 기존과 같은 단일 HTML로 유지한다. PDF에서 추출한 문항 이미지는 HTML 안에 포함해 인터넷 연결 없이도 작동하게 한다.

## 5. 전체 사용자 흐름

### 5.1 진단 시작

첫 화면에 미유 로고와 다음 기본 정보를 표시한다.

- 이름: 필수
- 진단일: 오늘 날짜 자동 입력, 수정 가능
- 퍼스널컬러: 선택 입력

이름이 비어 있으면 시작할 수 없고, 입력란 바로 아래에 이유를 표시한다.

### 5.2 문항 진행

- PDF 순서대로 1번 얼굴형부터 10번 이목구비 강도까지 진행한다.
- 한 화면에는 한 문항만 표시한다.
- 답변은 2×2 카드로 표시한다.
- PDF에 예시 이미지가 있는 답변은 실제 PDF 이미지를 카드에 사용한다.
- 이미지는 원본 비율 전체를 보여주며 강제로 잘라내지 않는다.
- 이미지를 누르면 확대해서 비교할 수 있다.
- 문항마다 최소 1개, 최대 2개를 선택한다.
- 선택한 답을 다시 누르면 해제된다.
- 2개를 선택한 상태에서 세 번째 답을 누르면 선택되지 않고 “최대 2개까지 선택할 수 있어요”를 표시한다.
- 답변이 없으면 `다음` 버튼을 비활성화한다.
- `이전`을 누르면 기존 선택을 유지한 채 이전 문항으로 돌아간다.

### 5.3 진행표

- 문항 화면 좌측 상단에 `진행표 5/10` 형태의 버튼을 둔다.
- 누르면 진행표가 왼쪽에서 열린다.
- 완료 문항, 현재 문항, 남은 문항을 구분한다.
- 완료 문항을 눌러 해당 문항으로 돌아갈 수 있다.
- 미완료 문항으로 건너뛰는 것은 허용하지 않는다.
- 세로 태블릿에서는 화면 너비 약 78%로 열고, 가로 화면에서는 과도하게 넓어지지 않도록 최대 너비를 둔다.
- ABCD 중간 점수는 진단 편향을 막기 위해 문항 진행 중에는 표시하지 않는다.

### 5.4 임시 저장

입력 정보, 문항별 선택, 현재 문항, 계산 점수, 최종 선택 타입을 현재 브라우저 탭에 임시 저장한다.

- 새로고침과 해설에서 뒤로 가기 후에도 복원한다.
- 브라우저 탭을 닫으면 보관이 끝난다.
- `새 진단 시작`을 누르면 모든 임시 정보를 초기화한다.
- 진행 중 새 진단을 누르면 초기화 확인을 한 번 거친다.

### 5.5 점수 계산

- 선택한 알파벳마다 1점을 더한다.
- 예: 한 문항에서 A와 B를 선택하면 A +1, B +1이다.
- 각 그룹의 점수 범위는 0~10점이다.
- 점수는 A, B, C, D 네 값으로 표시한다.

### 5.6 순위 계산

서로 다른 점수값을 높은 순서대로 정렬해 공동 순위를 적용한다.

- 예: A 8점, B 8점, C 6점, D 3점이면 A와 B는 공동 1위, C는 2위다.
- 1위 그룹은 분홍 아웃라인과 `1위` 라벨로 표시한다.
- 2위 그룹은 파랑 아웃라인과 `2위` 라벨로 표시한다.
- 순위 라벨은 점수 숫자 사이에 넣지 않고 강조 카드의 좌측 상단에 독립 배치한다.
- 1위와 2위 그룹의 3개 세부타입 카드에도 같은 순위 아웃라인을 적용한다.

### 5.7 최종 12타입 선택

PDF 순서대로 12타입을 한 페이지에 모두 표시한다.

1. A-1 판타지
2. A-2 프루티
3. A-3 소다
4. B-1 로맨틱
5. B-2 소프트
6. B-3 엘레강스
7. C-1 빈티지
8. C-2 세련
9. C-3 딥시크
10. D-1 카리스마
11. D-2 클리어
12. D-3 샤프

동작 원칙:

- 1위와 2위는 추천 근거일 뿐 선택 제한이 아니다.
- 컨설턴트는 점수와 무관하게 12개 중 하나를 선택할 수 있다.
- 타입 카드를 누르면 선택 상태만 바뀐다.
- 선택된 카드는 검은 아웃라인과 `선택` 라벨로 순위 표시와 구분한다.
- 하단의 `이 타입으로 확정하고 해설 보기`를 눌러야 이동한다.
- 확정 버튼에는 현재 선택한 코드와 타입명을 표시한다.

### 5.8 해설 직접 이동

기존 해설 식별자는 유지하고, 표시 코드와 순서만 PDF 기준으로 바로잡는다.

| 최종 타입 | 기존 해설 이동 주소 |
|---|---|
| A-1 판타지 | `#/cat/01` |
| A-2 프루티 | `#/cat/03` |
| A-3 소다 | `#/cat/07` |
| B-1 로맨틱 | `#/cat/05` |
| B-2 소프트 | `#/cat/06` |
| B-3 엘레강스 | `#/cat/09` |
| C-1 빈티지 | `#/cat/12` |
| C-2 세련 | `#/cat/16` |
| C-3 딥시크 | `#/cat/18` |
| D-1 카리스마 | `#/cat/13` |
| D-2 클리어 | `#/cat/08` |
| D-3 샤프 | `#/cat/17` |

해설에서 뒤로 가면 점수 합산표와 최종 선택 상태로 복귀한다.

## 6. 기존 HTML 순서 수정

현재 HTML의 화면상 D타입 연결은 다음과 같이 잘못되어 있다.

- 현재: D-1 클리어, D-2 샤프, D-3 카리스마
- 수정: D-1 카리스마, D-2 클리어, D-3 샤프

카드 글자만 바꾸지 않고 다음을 한 세트로 수정한다.

- 12타입 카드 순서
- 메뉴 순서
- 타입 코드와 이름 매핑
- 해설 이동 주소
- 내부 타입 배열
- 결과 화면

B와 C는 화면 표시 순서는 맞지만 기존 HTML 내부 섹션 순서가 각각 B-2/B-1/B-3, C-1/C-3/C-2로 섞여 있다. 유지보수 오류를 막기 위해 내부 순서도 PDF 순서로 정렬한다.

## 7. 문구 정리

진단 의미는 바꾸지 않고 명백한 오탈자와 띄어쓰기만 바로잡는다.

- `샹향형` → `상향형`
- `여성 스러운` → `여성스러운`
- `좁은이마` → `좁은 이마`
- `웃강` → `웃상`

진단 기준 자체의 표현 개선은 별도 검수에서 진행한다.

## 8. 시각·반응형 기준

### 8.1 우선 화면

- 1순위: 10~13인치 세로 태블릿
- 2순위: 태블릿 가로
- 기타 데스크톱·모바일에서도 기능이 깨지지 않게 한다.

### 8.2 태블릿 세로

- 답변 카드 4개는 2×2를 유지한다.
- 주요 터치 영역은 최소 44×44 CSS 픽셀 이상으로 만든다.
- 이전·다음 버튼은 화면 하단에서 쉽게 누를 수 있게 한다.
- 긴 문구는 카드 높이가 자연스럽게 늘어나며 잘리지 않는다.

### 8.3 이미지

- PDF에는 개별 이미지 35개가 포함되어 있다.
- 일부 이미지는 41×20픽셀 수준으로 작아 크게 확대하면 흐릴 수 있다.
- 원본 비율을 유지하고 `contain` 방식으로 전체를 보여준다.
- 12타입 얼굴 사진은 PDF 합성표에서 선과 글자를 제외해 다시 자른다.
- 더 높은 해상도 원본이 제공되면 같은 자리에 교체할 수 있게 한다.

### 8.4 로고

- 전달받은 `로고.png`를 사용한다.
- 시작 화면에서는 크게 표시한다.
- 문항과 결과 화면에서는 상단 중앙에 작게 표시한다.
- 진행표 내부에도 동일한 로고를 사용한다.

## 9. 기술 구조

기존 단일 HTML 구조를 유지하면서 최소 범위로 추가한다.

- 진단 데이터: 10문항, A/B/C/D 선택지, PDF 이미지
- 진단 상태: 기본 정보, 문항별 선택, 현재 문항
- 점수 계산: 선택값을 순수 계산 함수로 분리
- 순위 계산: 공동 순위를 처리하는 순수 계산 함수로 분리
- 화면: 시작, 문항, 결과, 기존 해설
- 저장: 브라우저의 탭 단위 임시 저장
- 이동: 기존 해시 주소 방식 유지

외부 서버나 새 라이브러리를 추가하지 않는다.

## 10. 오류 처리

- 이름 누락: 시작 버튼 비활성화와 필드 안내
- 문항 무응답: 다음 버튼 비활성화
- 3개째 선택: 기존 2개는 유지하고 최대 선택 안내
- 저장 데이터가 깨짐: 안전하게 초기화하고 첫 화면으로 이동
- 알 수 없는 타입 주소: 기존 인덱스로 이동
- PDF 이미지 로드 실패: 대체 문구를 표시하고 답변 선택은 가능하게 유지

## 11. 검증 기준

### 기능

- 10문항을 순서대로 완료할 수 있다.
- 모든 문항에서 1개 또는 2개 선택이 가능하다.
- 세 번째 선택은 차단된다.
- 이전 이동 후 답이 유지된다.
- 선택한 알파벳 점수가 정확히 합산된다.
- 공동 1위와 공동 2위가 정확히 표시된다.
- 12타입 모두 선택 가능하다.
- 각 타입이 정확한 기존 해설로 이동한다.
- 해설에서 뒤로 가면 결과가 유지된다.
- 새로고침 후 현재 상태가 복원된다.
- 새 진단 시작 후 모든 상태가 초기화된다.

### 순서

- PDF와 화면의 10문항 순서가 일치한다.
- 12타입이 A-1부터 D-3까지 PDF 순서와 일치한다.
- D타입이 카리스마, 클리어, 샤프 순서로 표시된다.

### 화면

- 세로 태블릿에서 답변 2×2 카드가 읽기 쉽다.
- 진행표가 왼쪽에서 열리고 닫힌다.
- 가로 태블릿에서도 카드와 진행표가 겹치지 않는다.
- 얼굴 사진이 잘리지 않는다.
- 순위 라벨과 점수 숫자가 겹치지 않는다.
- 손가락 터치 영역이 충분하다.

### 회귀

- 기존 12타입 해설, 검색, 무드북, 출력 기능이 유지된다.
- 기존 해설 주소를 직접 열어도 정상 표시된다.

다음 조건을 모두 만족해야 v17 완료로 본다.

1. 위 기능·순서·화면·회귀 검증을 통과한다.
2. 세로 태블릿과 가로 태블릿 화면을 직접 확인한다.

4. 최종 v17 파일의 실제 경로, 크기, 해시를 확인한다.
